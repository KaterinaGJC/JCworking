## 二、改动清单（Before / After）

| Before | After | Why |
| --- | --- | --- |
| `transition: transform .1s, background var(--dur)` | `transition: transform var(--dur-press) var(--ease-out), background var(--dur)` （`--dur-press:160ms`） | 指定具体属性，并用强 ease-out；松手回弹才有"跟手"的实感 |
| `.btn:active{transform:scale(.96)}`（无过渡） | `.btn:active{transform:scale(.97)}` + 160ms 过渡 | 按下立刻缩、松开平滑回弹；0.97 比 0.96 更克制 |
| `.sheet{animation:slideup .22s cubic-bezier(.2,.8,.3,1)}` | `.sheet{transition:transform 240ms var(--ease-drawer), opacity 200ms var(--ease-out)}` + `@starting-style{transform:translateY(100%)}` | 关键帧被打断会从零重播；transition 可以重定向，连点两次面板不跳帧 |
| `.toast{animation:fadein .16s ease}` | `.toast{transition:transform 180ms var(--ease-out), opacity 140ms var(--ease-out)}` + `@starting-style{translate(-50%,8px)}` | 提示条是"连着弹"的典型场景，必须可打断 |
| `.confirm{animation:fadein}` / `.confirm .box{animation:fadein}` | 遮罩淡入 140ms + 方框 `scale(.96)→1`，180ms | 元素不要凭空出现；模态框保持从中心（不是 origin-aware，那是弹层的规则） |
| 无减动效支持 | `@media (prefers-reduced-motion: reduce){ … }`：去掉所有位移与过渡，保留极短淡入 | 前庭功能敏感的用户会因为位移动画眩晕；**减少 ≠ 全部关掉** |
| `if (moved && dx < -90)` 删除便签 | `dx < -90 || 速度 > 0.11 px/ms` 即删除 | 甩卡片的直觉是"快就删"，只判距离会让人甩两次才成功 |
| 内置 `ease` / `.2,.8,.3,1` | `--ease-out:cubic-bezier(.23,1,.32,1)`、`--ease-in-out:cubic-bezier(.77,0,.175,1)`、`--ease-drawer:cubic-bezier(.32,.72,0,1)` | 内置曲线太软；自定义曲线才有"这是被设计过"的手感 |

## 三、防退化：测试把这些规则钉死了

`tests/v2/18-design-eng.test.mjs`（14 条断言，已纳入 `run-all`）：

1. CSS 里不得出现 `transition: all`
2. 不得出现 `scale(0)`
3. 不得出现单独的 `ease-in`
4. 必须定义 `--ease-out` 自定义曲线
5. 必须有 `prefers-reduced-motion` 处理
6. 弹层 `animation-name` 必须是 none（即不能用关键帧）
7. 弹层必须用 transform 过渡
8. 提示条同上
9. 按钮带 transform 过渡
10. 主按钮回弹时长在 100–160ms 区间
11. 快速甩（70px、极短耗时）能删除便签
12. 慢速拖 70px 不会误删
13. 减动效模式下淡入 ≤50ms
14. 减动效模式下弹层无位移过渡

> 以后谁再改样式，跑一遍 `node tests/run-all.mjs` 就知道有没有把这几条破坏掉。

## 四、没有采纳的部分（以及为什么）

| 指南里的建议 | 本次不做 | 原因 |
|---|---|---|
| Spring 动画（`useSpring` / 物理弹簧） | 不做 | 需要 Framer Motion / JS 运行时；本项目零依赖，且位移场景只有抽屉，CSS 曲线够用 |
| `clip-path` 揭示动画、hold-to-delete（长按 2s 渐显删除） | 不做 | 锦上添花，会增加误操作风险；删除已有确认/撤销 |
| Stagger 入场（列表逐条出现 30–80ms 延迟） | 暂不做 | 每次切页都 stagger 会让常用操作变慢；指南也说"装饰性、别挡交互" |
| Tooltip 的"第二次秒开" | 不涉及 | 我们没有 tooltip（触屏） |
| 3D transform / 鼠标跟随 | 不涉及 | 无鼠标场景 |

## 五、对「复古风格改版」的约束

新界面（`设计/v3-复古风格/`，待审批）在动效上同样受这份指南约束，且**复古风要额外注意**：

- XP 时代的界面几乎**没有动效**——这反而正好符合"高频操作不做动画"的原则
- 因此复古版会：**保留按下反馈（scale 0.97）**、**去掉页面切换的位移动画**（只留极短淡入）、弹层保留 200ms 左右的上滑
- 按钮的 3D 斜面（渐变 + 内阴影）是**静态**的，不要做"按下整块下沉"的位移动画——那在手机上会显得迟钝
